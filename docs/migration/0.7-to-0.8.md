# Migrating from 0.7.1 to 0.8 Request capabilities

0.8 keeps protocol v2 and the Simple API unchanged, but makes the Core
`Request` value platform-neutral. This is a source-level change for handlers
that used the old Linux-only members.

## Request shape

`Request` now contains `route`, `body`, and `request_id` only. It is explicitly
move-only, as it was effectively before because it contained `OwnedFd`.
Aggregate construction is no longer supported; server applications normally
receive `const Request&` and do not construct one themselves.

## Peer credentials

Replace:

```cpp
server.on("/who", [](const easy_uds::Request& request) {
    return std::to_string(request.peer.pid);
});
```

with an opt-in contextual route:

```cpp
#include <easy_uds/posix.hpp>

server.on("/who", easy_uds::RouteOptions{
    [](const easy_uds::Request&, const easy_uds::RequestContext& context) {
        const auto peer =
            easy_uds::posix::request_capabilities(context).peer_credentials();
        return easy_uds::Response{
            200, peer.present ? std::to_string(peer.pid) : "unavailable"};
    }});
```

`PeerCredentials::present` remains the capability-availability indicator. A
PID is metadata, not an authorization decision.

## Received descriptors

Replace `request.fd` with the handler-scoped borrowed view:

```cpp
const easy_uds::BorrowedFd fd =
    easy_uds::posix::request_capabilities(context).received_fd();
if (!fd.valid()) {
    return easy_uds::Response{400, "descriptor required"};
}
```

The request job remains the unique owner. To retain a descriptor after the
handler returns, call `fd.duplicate()` and move the resulting `OwnedFd` into
application-owned storage. `BorrowedFd` never closes or transfers ownership.

No retry/replay, transport, or wire-format behavior changes in this migration.
