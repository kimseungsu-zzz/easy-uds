# easy-uds v0.8.0-rc.1 — Cross-platform Core

Fast by default. Easy by design. Powerful when needed.

0.6 focused on building and validating the engine. 0.7 focused on making it
easier and safer to use. This 0.8 candidate carries that engine to Windows
without pretending that Linux-only capabilities are portable.

## Candidate scope

- Linux behavior, protocol v2, persistent Session, streaming, FD passing, peer
  credentials, backpressure, queue policies, and performance gates remain the
  reference behavior.
- Windows 10+ uses a concrete Winsock AF_UNIX backend selected by CMake. The
  candidate covers Core fixed RPC, concurrent Session requests, streaming,
  Simple API, lifecycle, and installed package consumers.
- The common Request is platform-neutral and remains explicitly move-only.
  POSIX request capabilities are delivered through the POSIX extension only.

## Intentionally unsupported

Windows resource/HANDLE passing, Linux-style peer credentials or SID identity,
generic native handles, automatic retry/replay, typed RPC, protocol v3, C and
Python bindings, and IOCP optimization are outside this candidate.

## Validation boundary

The Linux release gate and architecture guard are required. The Windows
workflow builds static and shared variants, runs the expanded Core/Session/
streaming/Simple/lifecycle smoke, installs the package, and builds/runs the
installed consumers. This development environment has no MSVC, so the
candidate's Windows result comes from Actions; the current candidate passed
in [run 31916904359](https://github.com/kimseungsu-zzz/easy-uds/actions/runs/31916904359).
A failure on a later candidate is a normal bug to fix on the current branch;
it does not justify rewriting `v0.7.1`.
