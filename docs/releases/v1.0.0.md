# easy-uds v1.0.0 — Stable

Fast by default. Easy by design. Powerful when needed.

easy-uds 1.0.0 freezes the compact C++17 local-IPC contract validated through
the 0.9 stabilization line. It is a stability and compatibility release, not
a new transport or feature experiment.

## What is supported

- Linux production backend and Windows 10+ Winsock AF_UNIX backend
- Core fixed RPC, persistent multiplexed Session, streaming, deadlines,
  bounded concurrency, backpressure, serialized domains, and queue policies
- Beginner `easy_uds::simple` Server/Client facade with `ResponseError`
- CMake install/export package and static/shared consumers
- Protocol v2 with the existing 20-byte header, request IDs, and streaming
  frame semantics

## Public contract

`Server`, `Client`, `Session`, `Request`, `Response`, `RequestContext`,
`Stream`, `Error`, route options, queue policies, statistics, and the Simple API
retain their validated 0.9 behavior. `Request` and `Session` remain move-only.
`OwnedFd` is a unique POSIX descriptor owner; `BorrowedFd` is a non-owning view;
`duplicate()` is explicit. See the [1.0 compatibility contract](../api/compatibility.md).

## Platform boundaries and limitations

POSIX peer credentials and `SCM_RIGHTS` descriptor passing are available only
on POSIX builds. Windows does not provide HANDLE/resource passing, SID/token
identity, or a generic `NativeHandle`. The release also does not include typed
RPC, protocol v3, C/Python bindings, IOCP optimization, automatic retry,
automatic replay, automatic reconnect, a logging/metrics framework, or another
transport.

The library is local IPC, not an authentication, authorization, encryption, or
network-RPC protocol. Applications decide whether a failed operation is safe
to retry; easy-uds never retries or replays implicitly.

## Migration from 0.9

The 0.9 public behavior is the 1.0 baseline. Existing Core, Session, Simple,
streaming, queue, and POSIX-capability code does not need a migration rewrite.
Review the [compatibility contract](../api/compatibility.md) and
[troubleshooting guide](../guides/troubleshooting.md) when moving package
consumers to the 1.0 version.

## Validation evidence

The final release candidate was validated by push CI
([31924423276](https://github.com/kimseungsu-zzz/easy-uds/actions/runs/31924423276))
and the full workflow
([31924489686](https://github.com/kimseungsu-zzz/easy-uds/actions/runs/31924489686)).
Both runs were green. Required jobs cover GCC/Clang static/shared,
Windows static/shared Core/Session/Simple/package, public headers, architecture
guards, ASan/UBSan, TSan, fuzz, stress/soak, ARM64, native x86_64 benchmarks,
and the release gate.

Representative native shared-Session measurements from the full workflow are
shown below. CPU is normalized CPU-seconds per million requests; Linux x86_64
and ARM64 are separate baselines, not directly comparable hardware targets.

| Platform / concurrency | Throughput | p50 | p99 | CPU / 1M |
| --- | ---: | ---: | ---: | ---: |
| x86_64 c1 | 34.7k req/s | 28.2 us | 43.4 us | 45.5 |
| x86_64 c8 | 43.5k req/s | 150.3 us | 708.2 us | 79.1 |
| x86_64 c32 | 34.6k req/s | 894.8 us | 2.57 ms | 109.4 |
| ARM64 c1 | 48.8k req/s | 20.3 us | 22.6 us | 32.5 |
| ARM64 c8 | 48.8k req/s | 103.8 us | 795.6 us | 67.5 |
| ARM64 c32 | 36.4k req/s | 854.8 us | 2.55 ms | 104.6 |

The warmed Session allocation probe reported **0 allocations/request** on both
architectures.
